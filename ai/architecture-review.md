# Architecture assessment prompt

Before recommending architecture changes, document:
- Product capabilities and non-functional requirements
- Teams, ownership and deployment boundaries
- Frameworks, repo structure, modules and dependency graph
- State management, API contracts, authentication and permissions
- Observability, CI/CD, test strategy, security controls
- Known incidents, bottlenecks and measured operational impact

Output: current-state summary, verified strengths, evidence-backed risks,
options with trade-offs, small reversible next steps and open questions.
Do not prescribe a monorepo, microfrontends or Design System by default.
